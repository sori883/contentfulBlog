# WRITEの書き方

このフォルダにMarkdownを追加すると、WRITEの一覧と個別ページになります。
公開への反映は通常のビルド・デプロイ時です。下書きは開発プレビューだけで確認できます。

## 新しく書く

```sh
pnpm write:new my-note
```

`contents/write/my-note/index.md` と `assets/` ができます。
フォルダ名は英小文字・数字・ハイフンです。URLは `/write/my-note` になります。
コマンドなしでフォルダとファイルを作っても同じです。

```markdown
---
title: 今日のメモ
updated: 2026-09-06
description: 一覧に添える短い説明（省略できます）
---

ここから本文です。

## 見出し

![写真の説明](./assets/photo.webp)
```

`title` と `updated` だけが必須です。更新日は実在する日付を `YYYY-MM-DD` で書きます。
一覧は更新日の新しい順です。ファイルの保存日時からは取得しません。
下書きにはフロントマターに `draft: true` を追加します（引用符は付けません）。
`pnpm dev` の開発サーバーでは表示されますが、本番ビルドの一覧・本文・サイトマップ・下書き専用画像には含まれません。
`draft` を省略するか `draft: false` にすると公開対象になります。作成コマンドではフラグを付けません。

## 画像

記事の `assets/` にPNG・JPEG・WebP・GIF・AVIFを置き、`./assets/ファイル名` で参照します。
日本語やスペース入りの名前も使えます。スペース入りの参照は `![説明](<./assets/今日の 写真.webp>)` と書きます。
サブフォルダも使えます。参照している画像だけが公開用にコピーされます。
外部画像は `https://...`、既存のpublic画像は `/me.webp` のように指定できます。
画像を差し替えるときは、キャッシュが残らないよう新しいファイル名にして参照を変更してください。

## プレビュー

```sh
pnpm dev
```

表示されたローカルURLで `/write` を開きます。Markdownや画像を保存すると再読み込みされます。
本番と同じ静的配信の確認は `pnpm preview` で行えます。このプレビューには下書きは表示されません。

見出し、リスト、引用、表、リンク、コードブロック、画像が使えます。
本文の `#` はページのタイトルと重複しないよう表示時に一段下の見出しへ変換します。
HTML・JavaScript・MDXの直書きは実行しません。
日付の間違いや存在しない画像は、ファイル名付きのビルドエラーになります。

`sample/` は `draft: true` の画像付き表示サンプルです。開発環境だけで表示されます。不要になったらフォルダごと削除してください。
